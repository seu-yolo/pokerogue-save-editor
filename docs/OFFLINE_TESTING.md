# 离线开发与测试

## 环境

- 游戏来源：[官方仓库](https://github.com/pagefaultgames/pokerogue)，tag `v1.12.0.11`，commit `e4e9b5383be7c9e171d32a9daaea2658d475c521`。
- 原联调路径：独立开发工作区的 `game/pokerogue-offline/`。本仓库不包含该目录；游戏需另行准备，官方图像、音频和语言子模块使用该 tag 指定的版本。
- Node.js 24.14.0；安装使用上游指定的 pnpm 10.33.2，不改变全局 pnpm。
- 官方 `app` 模式免登录；资源在本机，服务仅监听 `127.0.0.1:8000`。
- 游戏源码、资源、依赖和构建不与扩展一起提交或打包。保留上游 LICENSES 和素材许可文件。

## 启动和重建

原开发工作区通过 `启动肉鸽离线测试.command` 启动游戏，该脚本不包含在本仓库中。独立使用时，另行准备兼容的游戏构建，并将静态文件服务限定为 `127.0.0.1:8000`。打开 `http://127.0.0.1:8000/`，关闭终端或按 Control+C 停止服务。不要把服务改成监听 `0.0.0.0`。

修改游戏源码后，在 `game/pokerogue-offline/` 重建：

```sh
node node_modules/vite/bin/vite.js build --mode app
```

更新依赖时遵循官方锁文件和工具版本：

```sh
CI=true npx --yes pnpm@10.33.2 install --frozen-lockfile
```

首次下载或换版本，还需要官方 `git submodule update --init --recursive --depth 1`。不要把测试存档自动导入官网，也不要复用官网凭据。

## 离线扩展

在扩展仓库根目录执行：

```sh
npm run check
npm test
npm run pack:offline
```

Chrome → `chrome://extensions/` → 加载已解压的扩展程序 → 本仓库 `dist/RogueSave-Offline/`。该扩展有独立名称和安装路径，只能操作 `http://127.0.0.1:8000`，不会把官网账号当作测试存档。Chrome 权限匹配不区分端口，后台会再次检查完整 origin，以排除本机其他页面。

官网扩展继续使用 `dist/RogueSave/`，官网权限未增加。两个版本仍使用同一套游戏修改、事务和恢复代码，打包时只替换目标地址。

## 测试方式

从全新本机存档开始，或在离线游戏“菜单 → 数据管理”中分别导入兼容的账号／对局 `.prsv`。账号收藏和局内状态是不同文件。导入会覆盖对应数据，先导出当前离线存档。

建议顺序：

1. 确认离线游戏可启动，数据管理有“导入数据／导入对局”。
2. 新建测试对局，停在选择招式界面；扩展读取版本、波数、队伍。
3. 金钱预览／保存／刷新后持久化／同状态撤销。
4. 队伍恢复和增加道具，检查游戏内实际效果。
5. 收藏解锁、性格、闪光、蛋招式、特性；重新开局确认可选。
6. 券数保存，添加未知内容的传说蛋，确认计数及孵化进度。
7. 导出账号和对局，做一次修改后导入，确认确实恢复到导出时状态。
8. 等待下一次稀有遭遇，确认生成与刷新取消。

不把模拟测试通过写成实机已通过。测试结果在完成后单独记录；未验证项保留明确说明。
