# 开发与维护

## 本地命令

进入本仓库根目录后运行。需要 Node.js 20+；无需 `npm install`。

| 命令 | 用途 |
| --- | --- |
| `npm run check` | 检查 `src/`、`sidepanel/`、`scripts/`、`tests/` 内所有 JS/MJS 文件语法 |
| `npm test` | 扩展的全部自动化测试 |
| `npm run test:core` | 共用参数校验与备份处理 |
| `npm run test:game` | 页面适配、存档写入与游戏功能 |
| `npm run test:background` | 后台通信和事务协调 |
| `npm run test:static` | 版本、权限、DOM 与全部运行时源码检查 |
| `npm run pack` | 生成扩展目录和当前版本 ZIP |
| `npm run pack:offline` | 单独生成只连接 `127.0.0.1:8000` 的离线测试扩展，保留官网版产物 |
| `npm run preview:ui` | 本机 `127.0.0.1:4178/sidepanel/index.html` 合成数据界面预览；不连接游戏 |

上述命令只涉及本扩展，不依赖原工作区的根目录脚本或其他项目。

## 编辑与构建

只编辑本项目源码，不直接编辑 `dist/`。语法检查通过不代表功能正确；涉及功能时运行对应测试，交付前运行完整测试并打包。

打包收录 `manifest.json`、`src/`、`sidepanel/`、`LICENSE` 和 `THIRD_PARTY_NOTICES.md`；开发文档、测试、夹具和个人存档不进入扩展包。脚本对文件路径、普通文件及清单引用的已有检查继续保留。MIT 覆盖自有代码，第三方素材和字体保留各自许可。

输出位置：

- 本仓库 `dist/RogueSave/`：用于 Chrome “加载已解压的扩展程序”。
- 本仓库 `dist/RogueSave-v<version>.zip`：用于分享或手动安装。

打包会重新生成固定加载目录和同版本 ZIP，并在新 ZIP 完成后将历史官网／离线 ZIP 保留到 `dist/archive/`；当前版本两种 ZIP 都留在 `dist/`。不会清理旧版扩展文件夹或 `save/`，也不会覆盖同名历史归档；同名冲突时保留两份并报告错误。旧版文件夹可能被 Chrome 加载，不要随意移动或删除。

已经加载 `dist/RogueSave/` 时，重新打包后在 `chrome://extensions/` 点击该扩展的“重新加载”，再刷新游戏页、重新打开侧栏。不要在写入任务进行中重新加载扩展；刷新游戏页会取消尚未触发的一次性遭遇等待。

离线环境的下载、启动、独立扩展配置和实机验证范围见 [OFFLINE_TESTING.md](OFFLINE_TESTING.md)。普通版本的 `src/shared/game-target.js` 固定官网 origin；离线打包仅在独立输出中替换为本机 origin，正式版不增加本机访问权限。

## 游戏更新适配

当前源码声明支持 `1.12.0.10`、`1.12.0.11`；这不是实时查询的最新官方版本。更新游戏适配时：

1. 核对官方版本与源码，重点检查场景导出、存档解析和保存接口、状态恢复、扭蛋生成、遭遇池及 `randomSpecies` 调用链。
2. 按实际变化修改 `src/game/page-adapter.js`，并让模拟游戏测试覆盖新的行为；不能只把新版本号加进列表。
3. 同步 `src/shared/core.js` 的 `SUPPORTED_GAME_VERSIONS` 与适配器函数内的 `SUPPORTED_VERSIONS`。
4. 运行完整测试、打包，再使用可恢复的测试存档验证页面识别、预览、保存回读及撤销。账号蛋与一次性遭遇按实际功能验证，避免操作用户正在游玩的对局。
5. 更新 README 的已适配范围，明确哪些是源码与模拟测试验证、哪些实际在浏览器验证。

不支持的新版本继续保持现有只读处理，不通过删除版本检查、白名单验证或事务保护来适配。

## 扩展版本与入口维护

当前扩展版本 `1.0.0`。界面与仓库首页统一为训练家手册风格，支持范围仍为游戏 `1.12.0.10` 和 `1.12.0.11`。调整发布版本时，同步：

- `manifest.json` 的 `version`；
- `package.json` 的 `version`；
- `src/shared/core.js` 的 `EDITOR_VERSION`；
- `src/game/page-adapter.js` 函数内的 `ADAPTER_VERSION`；
- `THIRD_PARTY_NOTICES.md` 和 README 中的版本及 ZIP 名称。

移动入口时同步清单、ES module 导入、测试导入和文档。`check.mjs` 与静态源码测试递归发现各自目录下的 JS/MJS 文件，后续新增模块不用维护手写文件清单；`src/`、`sidepanel/` 以外的新运行时目录仍需同步检查与打包范围。

## 1.0.0 首发验证

177 项自动化测试及 26 个 JavaScript 文件语法检查通过。独立离线 Guest 使用当前页面适配器完成局内保存、同状态撤销、账号修改和重载核对；未操作官网账号，也未替换 Chrome 已加载的扩展。扩展后台通信有自动化回归覆盖，不能将页面适配器测试称为完整的浏览器扩展端到端测试。结果与未验证项见 [首发审查](REVIEW-2026-10-06.md)。

## UI 设计依据

界面使用深蓝像素菜单框、淡金主按钮和青绿状态色。局内、收藏、扭蛋和备份分别以金、紫、绿、青突出页签和标题；金额输入与全恢复优先展示，对局详情和解释性文字默认折叠。局内操作和永久资源分页，所有账号操作先展示修改内容。参考 [GitHub Primer 的分段导航原则](https://primer.style/product/components/segmented-control/)，键盘导航按 [WAI-ARIA Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)；表单保留可见标签和状态提示。洛托姆像素精灵图、手绘点阵图标和 OFL-1.1 中文字体均随扩展本地加载，见 [素材说明](ASSETS.md)，没有引入第三方 UI 库。
