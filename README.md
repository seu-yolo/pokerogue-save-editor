# 洛托姆口袋 · Rotom Pocket

一个本地运行的 Chrome 扩展，用来管理 PokéRogue 当前对局、永久宝可梦收藏和扭蛋资源。无需开发者工具，也不绑定某个存档或波数。

本仓库用于准备首次公开发布，暂未发布 GitHub Release。现有 `0.4.4` 是开发版本，首个公开版本计划使用 `1.0.0`，发布前会统一更新版本信息。自有代码许可证尚未确定，图片和字体继续使用各自的许可；当前不作为已授权自由使用的开源发行版。进度与待办见 [首发准备](docs/RELEASE_PREPARATION.md)。

- 当前版本：`0.4.4`（测试版）
- 已适配 PokéRogue：`1.12.0.10–1.12.0.11`
- 最低 Chrome：`116`

这不是 PokéRogue、Pagefault Games 或 Pokémon 官方工具。请只修改你自己有权控制的存档。

## 安装

仓库尚无公开安装包。现在可以按下文 [从源码验证和打包](#从源码验证和打包) 生成 ZIP，再按以下步骤加载。发布时会在 GitHub Releases 提供官网版和离线版安装包，GitHub 自动生成的源码 ZIP 不等同于扩展安装包。

1. 解压 `RogueSave-v0.4.4.zip`。
2. 打开 `chrome://extensions/`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择解压后直接包含 `manifest.json` 的扩展文件夹。
5. 刷新 PokéRogue 页面，然后点击 Chrome 工具栏中的“洛托姆口袋”。

从旧版升级时，先把新安装包解压到临时目录，再用其中的扩展文件更新原来已加载的目录，最后在 Chrome 管理扩展程序点“重新加载”。不要卸载原扩展或清空扩展数据，以免丢失本机备份和待确认记录。

已从工作区 `dist/RogueSave` 加载的扩展，可以保持该路径并在 Chrome 管理扩展程序点“重新加载”。其他电脑请使用新的 0.4.4 安装包。顶部“↻ 刷新”只刷新口袋的连接与核对状态，不加载新版扩展代码，也不刷新游戏页。

## 使用

1. 只保留一个 PokéRogue 游戏标签页，进入想修改的存档。
2. 停在等待选择招式的稳定界面。
3. 在侧栏输入金钱，或点“一键全恢复”。
4. 点“预览”，确认后点“保存修改”。

侧栏分为“局内／收藏／扭蛋／备份”四页。首次使用先到“备份”下载原生对局和账号 `.prsv`，尤其是修改永久收藏之前。

在“收藏”页搜索名字或编号，选择宝可梦，再选择闪光外观、合法初始形态、性格、蛋招式与特性，点“查看解锁内容”后确认保存。已有解锁只会保留和补充；不会将宝可梦放进当前队伍，下一次开局时从初始选择页面使用。性格可多选并显示能力增减，稀有蛋招式会单独标记；没有对应闪光变体或形态的选项不可选。

“扭蛋”页可以输入四种抽奖券的目标总数量，也可以添加未知内容的传说蛋。添加蛋只固定传说层级；物种、闪光、变体、隐藏特性和蛋招式继续由游戏官方流程随机生成，侧栏不会提前显示结果。每枚蛋保持官方 100 波孵化时间。

在“局内”的“添加道具”中读取列表，选择道具、数量及持有者，加入本次修改，再预览和保存。界面显示当前层数、官方上限、待添加数量和剩余额度，持有道具按选中宝可梦分别计算；修改现有道具层数时也会更新额度。比如已有 2 层闪光护符，上限为 4，加入 1 层后就只剩 1 层可添加。上限从当前游戏的道具对象读取，不统一写死为 99；保存时还会重新检查。支持一组明确的永久／持有道具，不支持任意生成器道具。

想让下一层出现当前地形的稀有宝可梦时，在“一次性遭遇”卡片点“等待下一次极稀有遭遇”。修改器会一直等到下一次野生战斗，在生成当刻读取实际地形，并按 `ULTRA_RARE → SUPER_RARE → RARE` 选择最高非空官方池；Boss 层使用对应 Boss 池最高档。训练家层不会消耗，双打只影响第一只。它不会预览物种，也不会改变官方生成的等级、形态、性别、特性、招式、IV 或闪光结果。刷新游戏页面会取消等待。

修改器会自动识别当前槽位、波数和队伍，所以切换存档或推进到其他波数后仍可使用。切换后先点右上角刷新按钮即可。

第一次使用前，建议点“下载原生 `.prsv`”留一份游戏自己的备份。

## 可以修改什么

| 功能 | 范围 |
| --- | --- |
| 金钱 | `0–9,007,199,254,740,991`（官方安全整数上限），支持无尽模式大金额；自定义目标总金额，不提供预设或增量按钮 |
| 队伍恢复 | HP 全满、清除异常、PP 全满 |
| 精灵球 | 五种常用球各 `0–99` |
| 队伍进阶 | 亲密度、宝可病毒、暂停进化、六项 IV 设为 31 |
| 道具 | 修改部分现有道具的层数；新增护符、地图、经验道具、吃剩的东西、多重镜等受支持道具 |
| 对局名称 | `1–40` 个字符 |
| 随机传说蛋 | 每次 `1–10` 枚，可选传说 UP、蛋招式 UP、闪光 UP；账号总蛋数不超过 99 |
| 一次性稀有遭遇 | 下一次野生战按实际地形使用最高非空官方稀有池；可随时取消 |
| 永久初始收藏 | 定向解锁当前版本合法初始宝可梦；普通／黄蓝红闪、初始形态、性格、蛋招式、普通与隐藏特性 |
| 抽奖券 | 四种券各 `0–9,999`，设置目标总数量 |

常用的金钱和恢复会直接显示；其余功能折叠在“更多资源修改”“队伍进阶修改”和“现有道具层数”中。

不会指定蛋内物种，也不会直接修改波数、种子、当前队伍的等级、经验、招式、闪光、融合或敌方数据。不增加收藏糖果、被动、成就或通关次数，不修改账号身份。随机传说蛋仍需正常孵化；永久定向解锁是“收藏”页的独立功能。

## 如果保存被拒绝

- “状态已变化”：游戏在预览后继续变化了，点刷新并重新预览。
- 收藏提示“账号数据已变化，请重新预览”：0.4.2 修复正常计时及跨扩展传递时的快照结构误报。更新安装目录后需在 Chrome 扩展管理页重新加载；只刷新游戏不会替换扩展代码。真实收藏、券或蛋发生变化时仍需重新预览。
- 道具修改提示 `session.party[...].hp` 不一致：0.4.3 修复 HP 道具的正常联动、回滚及撤销。旧的待确认记录不会自动删除；先更新扩展，重新载入游戏并停在稳定指令界面，再点顶部“↻ 刷新”核对。若仍不一致，保留 JSON／原生备份，不要卸载扩展或删除安全记录来绕过。
- “当前阶段不允许写入”：等回到选择招式界面后再试。
- “实际存档变化与白名单不一致”：`0.3.1` 已包含旧版常见的恢复状态和游戏解析器误报修复；若仍出现，先刷新游戏和侧栏再试。
- 黄色“结果待确认”：先不要继续操作游戏，点侧栏刷新。若提示旧页面可能仍在运行，请关闭原 PokéRogue 标签页，在新标签页重新进入同一存档后再刷新。
- “游戏版本不兼容”：游戏已更新，修改器会只读，需等待重新适配。

扩展会在每次写入前自动保存一份本地事务备份，并在写入后回读当前浏览器中的游戏缓存与实时状态。备份保存在扩展本地存储，不会上传。原生 `.prsv` 可留存或迁移至兼容的离线版；官网正式版没有账号／对局的菜单导入入口，导出不等于可以在官网回档。

账号保存使用官方 `saveSystem()` 的返回值和实时快照检查，并非独立查询服务器回读。账号保存失败或通信中断时，本地恢复成功也不代表服务器未写入，会保留“结果待确认”。请关闭原游戏标签页，新开同一账号，核对收藏、券和蛋后刷新侧栏。

局内修改（包括新增道具）可在同一修改后状态下撤销。账号收藏／券／蛋暂不提供一键撤销，也没有官网原生导入恢复的保证。兼容离线版可导入修改前的原生账号 `.prsv`；恢复会覆盖相应存档而不只是取消单项修改。本地事务 JSON 用于记录与排查，不能直接导入游戏；JSON 的已有完整性校验只覆盖其中的对局快照，不覆盖账号快照。

## 离线测试环境

离线游戏需要另行准备，本仓库不包含游戏本体、资源或启动脚本。原开发环境使用官方 `v1.12.0.11` 的 `app` 模式，免登录且使用浏览器本机存档。

将兼容的离线游戏服务运行在 `http://127.0.0.1:8000/`，再使用离线测试扩展。离线数据与官网账号分开；不要切换到 `localhost` 或另一个端口，否则浏览器会使用不同的存储空间。

执行 `npm run pack:offline` 可生成独立的 `dist/RogueSave-Offline/` 与 ZIP。Chrome 加载这个目录即可测试；离线扩展只允许本机地址，并严格核对端口 8000，不访问官网账号。正常 `npm run pack` 仍生成只连接官网的版本，两个扩展的记录和存储也分别隔离。

安装与实机测试记录见 [离线测试说明](docs/OFFLINE_TESTING.md)。

## 项目导航

- `src/shared/`：侧栏与后台共用的校验、版本信息和备份摘要。
- `src/background/`：扩展后台、页面通信、本地备份与事务协调。
- `src/game/`：注入 PokéRogue 页面、操作当前对局与调用官方游戏逻辑。
- `sidepanel/`：用户界面。
- `tests/`：自动化测试；合成夹具统一放在 `tests/fixtures/`。
- `scripts/`：语法检查和打包工具。
- `docs/`：[文档导航](docs/README.md)、[架构与代码定位](docs/ARCHITECTURE.md)、[开发与游戏更新适配](docs/DEVELOPMENT.md)。

需要 Node.js 20 或更高版本，不依赖第三方 npm 包。在本项目目录执行：

```bash
npm run check
npm test
npm run pack
```

本仓库可以独立克隆和运行，不依赖原开发工作区的其他项目。无需 `npm install`。专项测试和代码定位见 [开发说明](docs/DEVELOPMENT.md)。

产物：

- 仓库内的 `dist/RogueSave/`
- 仓库内的 `dist/RogueSave-v0.4.4.zip`

打包输出限定在本仓库的 `dist/`，不处理个人存档。旧版官网／离线 ZIP 自动保留到 `dist/archive/`，旧版已解压文件夹继续原位保留；当前版本两种 ZIP 留在 `dist/`。`dist/` 不提交到 Git，目录约定见 [文档导航](docs/README.md)。

## 权限

扩展只申请：

- `scripting`：读取和修改 `pokerogue.net` 当前对局；
- `sidePanel`：显示侧栏；
- `storage`：保存本地备份和事务状态；
- `https://pokerogue.net/*`：把页面访问范围限制在 PokéRogue。

扩展不读取 Cookie、密码或浏览历史，也不把存档发给第三方服务器。

第三方与商标说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
